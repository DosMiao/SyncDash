# SyncDash contributor guide

SyncDash is a safety-first file synchronization tool with one Rust core library and two shells: a CLI and a Tauri v2 desktop app with a React 19 webview. Its central workflow is `scan -> compare -> apply`; snapshot tables, plans, and events are inspectable JSONL artifacts. It supports local paths, mounted shares, VFS roots, SSH peers, multiple targets, and the `mirror`, `sync`, and `enrich` modes.

All code, identifiers, comments, documentation, and product text use English and en-US spelling. Respond to the user in English even when instructions are written in Chinese.

## Repository map

- `Dev/src/`: the `syncdash` library and CLI. Its physical tree encodes `base -> services -> workflow -> application -> shell`; `lib.rs` maps that tree to the stable public modules.
- `Dev/src-tauri/`: the complete desktop crate. Its source is grouped into the app composition root, wire contracts, stateful features, and thin IPC commands.
- `Dev/typescript/core/`: generated contracts, pure domain/application logic, Tauri and preference infrastructure, and shared framework-free helpers.
- `Dev/typescript/ui/`: feature-owned React code, workspace/progress page controllers, shared UI
  primitive families, and thin independent window composition roots.
- `Dev/typescript/styles.css`: the complete design-token and styling layer.
- `Dev/typescript/core/types/generated/`: Rust wire types generated by ts-rs.
- `Dev/ARCHITECTURE.md`: cross-language placement and dependency rules.
- `dist/`: committed frontend build output embedded by Tauri.
- `README.md`: user-facing architecture, behavior, usage, and build guide.
- `.docs/0 dev note.md` is the user's personal file and must remain untouched.

The authoritative Rust layer contract and its accepted exception are documented in `Dev/src/lib.rs`.

## Work supported here

Contributors may implement or refactor core sync behavior, storage, VFS backends, CLI commands, Tauri IPC, React UI, job-schema migrations, tests, build integration, and documentation. Contract changes should be completed across every caller and layer in one coherent change. Update `README.md` and relevant module headers whenever user-visible behavior or an invariant changes.

## Commands and tools

Use `rg` and `rg --files` for code discovery. Read implementations and call sites before changing behavior.

Use the smallest relevant check while developing. The default cross-language test loop is:

```bash
npm test
```

`npm test` runs Rust library/binary tests and executable frontend behavior tests. Use focused
package, module, or test-name filters during iteration. Run `npm run test:integration` after
changes to apply, package, restore, leases, or filesystem transactions. Run
`npm run test:frontend:audit` after changing TSX structure, CSP-sensitive layout, IPC
registration, capabilities, or permissions. `npm run test:all` is the release and broad-refactor
suite; do not rerun it after unrelated edits.

Before handoff, format and type-check the affected languages. Rust changes also require the
workspace check and warning gate:

```bash
cargo fmt --all -- --check
cargo check --workspace --all-targets
cargo clippy -p syncdash-desktop --all-targets --no-deps -- -D warnings
npm run typecheck
```

Platform-conditional code follows the "Platform seams" section of `Dev/ARCHITECTURE.md`. After
changing a platform seam (`base/fs`, `base/foundation/host.rs`, watch, local discovery, localid,
or the desktop autoscan worker), also run `npm run check:cross`; it type-checks the library and
CLI for the foreign supported hosts and names any target it cannot verify on this machine. A
target it reports as unverified must be checked natively (`cargo check --workspace --all-targets`
on that host) before the change is considered complete.

After changing a Rust type annotated with `#[ts(export_to = ...)]`, regenerate the frontend contract:

```bash
npm run gen:types
```

After any frontend change, refresh the committed bundle:

```bash
npm run build
```

Use the repository Builder for project builds, development launches, optimized artifacts, installers, and running built artifacts. Before any Builder or maintenance action, read `../../0_devControl/builder/skills/builder-workflow/SKILL.md` on macOS or Windows.

```bash
./builder.command info
./builder.command dev
./builder.command build dist
./builder.command build 123
./builder.command build cli
./builder.command run dist
```

On Windows, use the corresponding `builder.bat` commands. `cargo check`/`test`, type generation, and the documented `npm run build` dist refresh remain direct commands. Optimized Dist, Max, Release, and compact numbered tiers build only the desktop artifact; on Windows it stays inside the checkout under `target/builder-tiers/<tier>/` (build/deep cleanup holds it in `tools/builder/.rescue/` across the deletion), while macOS publishes it to the durable Builder artifact store. `build cli` is the sole standalone-CLI Builder path, uses Dist policy, and writes `target/release/syncdash[.exe]` (macOS additionally publishes a durable copy); optimized desktop tiers never build it implicitly.

A desktop process may be closed by Builder when replacing its binary. A running `syncdash` CLI may be applying changes and holding root leases, so report it and obtain explicit approval before terminating it. Interactive GUI acceptance remains the user's step unless they ask for a launch.

## Core engineering contracts

- Data safety comes first. Dry-run is the default, writes require explicit Apply, conflicts are reported rather than guessed, and overwritten/deleted data goes through trash or versioning. Missing, malformed, stale, unsupported, or incomplete evidence fails at its source instead of producing a default or partial result.
- Rust dependencies point downward through the layers. Keep single-file domains flat, recursively
  group multi-responsibility domains by model, policy/state, persistence, coordination, and
  execution ownership, give `mod.rs` real content, and keep dependency edges visible. Do not create
  generic `support`, `helpers`, `utils`, or `common` buckets.
- `run` is the single transport router. A `peer://` root means the far-side SyncDash scans and applies; `sftp://`, `ftp://`, `ftps://`, and `smb://` are VFS roots operated by this process. Root phrases are the sole authority for location, while credentials live in the OS credential store.
- New VFS backends implement the synchronous `Vfs` trait and pass `Dev/src/base/fs/vfs/conformance.rs`. Pipeline tests use `MemVfs`; `LocalVfs` exercises a different lane.
- Functional code is preserved unless its removal is explicitly in scope. When changing an API, update every caller directly rather than leaving compatibility forwarding paths. Fix warnings at the cause.
- Rust-to-TypeScript wire data stays `snake_case`. Annotate 64-bit integers for JSON-compatible TypeScript numbers, regenerate through `npm run gen:types`, and edit generated files only through that process.
- Frontend components use IPC only through `Dev/typescript/core/infrastructure/tauri/`. Main- and
  progress-window command adapters remain separate so one page cannot import the other page's
  authority. Page controllers compose typed runtime owners and presentation; they do not import
  infrastructure directly. Pure domain and application modules never import infrastructure or UI.
  Execution membership belongs to Run Scope and stays in engine plan order; grouping, sorting,
  folding, and path display are presentation only. Pending or failed filters fail closed, and manual
  Apply is available only for authenticated Difference results.
- A successful desktop Compare is immutable evidence identified by a random 128-bit `result_id` and retained in the disk-backed Compare-result repository. Backend hot-cache eviction, workspace close, navigation, and candidate dismissal never delete it. In-session workspaces have no silent scope limit and preserve complete presentation/review state; after process restart the immutable result is viewable but execution is expired until a fresh Compare. Only explicit forget removes evidence.
- Comments earn their place by preserving a non-obvious invariant, caller contract, external fact, intentional exception, or actionable ownership. Delete comments that restate the code, and verify every factual claim in a touched comment against its current source of authority.
- Tests protect behavior, safety boundaries, and supported persisted formats. Do not test source
  spelling, function layout, or one-time implementation details. Repository-wide dependency and
  delivery policies belong in the explicit architecture audit suite, not the default feedback loop.
- Styling lives in `Dev/typescript/styles.css`: use its tokens, keep text at least 11px, maintain 4.5:1 contrast, and use webview zoom. Tauri CSP makes inline styles unreliable.
- Tauri commands remain thin and do not call other command modules; shared native adapters live
  under `ipc`. Apply/Compare preparation, review, target validation, and execution belong under
  `features/operations`; their command handlers only authorize the window, extract state/arguments,
  and delegate. Blocking engine work uses `spawn_blocking` and the `ProgressEvent` stream. Commands
  creating a `WebviewWindow` are async, and child windows are destroyed when closed.

## Git and collaboration

Preserve unrelated work in the shared worktree. Check `git status` and the targeted diff before broad edits, then use focused patches and explicit pathspecs. Commit only when the user asks in the current message; commit directly on `main` unless they request a branch, and push only when requested.
